===============================================================================================
INTENÇÃO
===============================================================================================

O VIP de SPI será implementado como mestre ativo, operando no modo 0.

- spi_sclk inicia em nível baixo e permanece baixo quando ocioso.
- MOSI é amostrado pelo DUT na borda de subida de SCLK.
- MISO é atualizado pelo DUT na borda de descida de SCLK.
- MOSI deve estar estável antes da borda de subida.
- O frame possui 40 bits, transmitidos MSB-first.
- O período de SCLK deve ser configurável e seu intervalo mínimo confirmado no DUT.

Formato do frame:

    {RWb, ADDR[5:0], RSV, DATA[31:0]}

- RWb = 0: escrita.
- RWb = 1: leitura.
- RSV deve ser 0.
- ADDR = 0x3F identifica o frame NOP usado na leitura.

Operações:

Escrita:
1. Construir o frame de escrita.
2. Abaixar spi_cs_n.
3. Transmitir 40 bits MSB-first.
4. Finalizar com SCLK baixo.
5. Elevar spi_cs_n.

Leitura:
1. Construir e transmitir o frame READ.
2. Desativar spi_cs_n.
3. Aguardar o intervalo necessário.
4. Construir e transmitir o frame NOP.
5. Capturar MISO na janela válida.
6. Finalizar a transação.

Confirmado na prática:
- Os dados de retorno correspondem aos 32 bits menos significativos do frame NOP.
- CS_N é desativado entre os dois frames da leitura.

===============================================================================================
ARQUITETURA
===============================================================================================

Componente                Responsabilidade
spi_item                  Representar uma operação READ ou WRITE.
spi_cfg                   Configurar período, temporização e modo ativo/passivo.
spi_driver                Serializar frames e controlar CS_N, SCLK e MOSI.
spi_monitor               Capturar sinais físicos e reconstruir frames/operações.
spi_scoreboard            Verificar escritas e comparar dados de leitura.
spi_coverage              Cobrir registradores, operações, dados e condições.

Decisão arquitetural:
- A operação de leitura deve ser representada por um único spi_item de alto nível.
- A sequência solicita apenas a leitura de um endereço.
- O driver executa o READ Request e o frame NOP internamente.
- Isso mantém as sequências simples e concentra o protocolo no driver.

Frame interno:

    tx_frame = {RWb, req.addr, 1'b0, req.write_data}

Transmissão:
- tx_frame[39] até tx_frame[0].
- MOSI preparado com SCLK baixo.
- MISO capturado 1 ns após a borda de subida.
- CS_N elevado somente após completar os 40 bits.
- Pode ser necessária uma espera de 80 ns após o frame para sincronização com sys_clk.

Tasks previstas:

    task transfer_frame(input bit [39:0] tx_frame,
                        output logic [39:0] rx_frame);

    task spi_write(spi_item req);
    task spi_read(spi_item req);

Exemplo de frame de escrita:

    tx_frame = {
        1'b0,           // WRITE
        req.addr,       // 6 bits
        1'b0,           // RSV
        req.write_data  // 32 bits
    };

Sequência física de um frame:
1. Manter spi_sclk = 0 e spi_cs_n = 1.
2. Abaixar spi_cs_n e preparar o primeiro bit de MOSI.
3. Aguardar o intervalo de preparação de CS_N.
4. Gerar 40 ciclos de SCLK.
5. Finalizar com SCLK baixo.
6. Elevar spi_cs_n.

===============================================================================================
DRIVER
===============================================================================================

- Implementar o driver como mestre ativo.
- Controlar externamente clk e rst_n.
- Usar uma única task para transmitir um frame físico de 40 bits.
- Usar tasks específicas para WRITE e READ.
- Permitir que o período do SPI seja configurado.
- Ignorar spi_miso fora da janela válida de retorno.
- Tratar reset durante uma transferência.
- Verificar setup e hold de MOSI e CS_N.
- Caso CS_N seja desativado antes dos 40 bits, definir se o frame parcial será descartado.

===============================================================================================
MONITOR
===============================================================================================

O monitor escolhido será inicialmente por operação, mantendo internamente a identificação dos frames.

Fluxo:
1. Detectar a descida de spi_cs_n.
2. Capturar MOSI e MISO nas bordas de subida de SCLK.
3. Reconstruir os frames MSB-first.
4. Identificar WRITE, READ Request e NOP.
5. Associar o READ Request ao NOP seguinte.
6. Extrair miso_frame[31:0] como resultado da leitura.

Opções alternativas:
- Monitor por frame: publica um item para cada frame físico. A associação READ/NOP fica no scoreboard ou em outro componente.
- Monitor por operação: reconstrói a operação completa e publica uma leitura única, mesmo com dois frames.

Observação:
- O testbench escreve 32'd256 em REG_NUM_BLOCKS e verifica cfg_num_blocks[8:0] = 256.
- Após reset, cfg_num_blocks[8:0] deve receber 1.

===============================================================================================
DÚVIDAS
===============================================================================================

Alta prioridade:
- Em quais ciclos do frame NOP os 32 bits de MISO são transmitidos?
- Os bits de MISO começam alinhados ao campo DATA[31:0] ou em outro ciclo?
- Qual é o comportamento de MISO durante WRITE e READ Request?
- MISO deve ser considerado don't care fora da janela válida?
- Qual é o comportamento de MISO quando spi_cs_n = 1?
- Existe um intervalo mínimo entre READ Request e frame NOP?
- O DUT exige CS_N elevado entre os dois frames da leitura?
- Se CS_N cair antes dos 40 bits, o frame parcial é descartado?
- Qual é o comportamento do SPI se rst_n for ativado durante uma transação?

Prioridade média:
- Qual é o período mínimo de SCLK?
- Existem requisitos de setup e hold adicionais ao modo 0 para MOSI e CS_N?
- Como o DUT trata frames com RSV = 1?
- Como são tratados escritos em registradores somente leitura?
- Como são tratados escritos em endereços reservados?

===============================================================================================
RECOMENDAÇÕES
===============================================================================================

- SPI driver: mestre ativo.
- clk e rst_n: controlados externamente.
- Usar uma única task de transmissão serial de 40 bits.
- Usar tasks específicas para READ e WRITE.
- Tornar o período do SPI configurável.
- Implementar tratamento explícito de reset.
- Implementar monitor independente do driver.
- Reconstruir diretamente os frames a partir dos sinais físicos.
- Manter a interface de sequência simples: uma operação de leitura corresponde a um único spi_item.

Essas definições devem ser confirmadas no RTL antes de fechar temporização, captura de MISO e tratamento de frames incompletos.
